# Contributing to CPOA

CPOA should evolve from observed Claude Code behavior and real project outcomes rather than theoretical complexity.

When proposing a change, describe:

1. The concrete problem observed.
2. The project/task context in which it occurred.
3. The current CPOA behavior or rule involved.
4. The proposed change.
5. Expected impact on quality, context/tokens, cost, permissions or maintainability.
6. How the change can be verified.

Prefer small, evidence-backed changes. Avoid adding roles, layers or process unless a recurring need justifies them.

Changes to the core standard should update `CHANGELOG.md` and, where relevant, examples/templates/tests.
